# 계획

## 무엇을 만드는가
제조 라인의 외관 검사를 가정한 이상 탐지 검사기다. 정상 제품 사진만으로 검사기를 만들고, 불량이면 어디가 이상한지 히트맵으로 보여 준다. 만드는 것보다 **재는 것**이 중심이다. 공개 벤치마크의 AUROC는 이미 포화에 가까우므로, 현장에서 검사기를 실제로 굴릴 때 부딪히는 질문 네 개를 미리 정한 규칙으로 잰다.

## 질문
1. **결함 라벨 몇 장부터 지도 학습이 이기는가.** 정상 이미지만 쓴 이상 탐지와, 결함 라벨 k장(5/10/20/40)을 쓴 지도 학습을 같은 테스트셋에서 비교한다. 검증에 쓰는 결함 라벨도 비용으로 센다.
2. **고정한 임계값의 실제 오검출률은 목표와 얼마나 다른가.** 정상 이미지만으로 "오검출률 5%"에 맞춘 임계값이 테스트에서 실제로 몇 %가 되는지, 그 차이가 표본이 유한해서 생기는 뻔한 흔들림인지 절차의 편향인지를 이론값과 대조해 가른다. 밝기·흐림 같은 가벼운 촬영 조건 변화를 줬을 때 AUROC는 그대로인데 오검출률만 뛰는 구간이 있는지도 본다.
3. **합성 교란은 실제 조명 변화를 대신할 수 있는가.** 실제로 조명을 바꿔 찍은 데이터(M2AD) 안에서, 기준 조명 사진에 합성 교란을 준 결과와 실제로 다른 조명에서 찍은 결과를 같은 시편에서 비교한다. 새 조명의 정상 사진 몇 장으로 다시 맞추면 얼마나 회복되는지도 잰다.
4. **지연 예산 안에 남는 구성이 있는가.** 메모리 뱅크 크기, 입력 해상도, 백본, 양자화가 검출 성능과 고정 임계값의 오검출률을 얼마나 바꾸는지, CPU에서 장당 200ms 안에 들어오면서 2번의 기준을 지키는 구성이 남는지 본다.

## 방법
- **PatchCore** (직접 구현): 사전학습 백본의 패치 특징을 메모리 뱅크에 모으고 가장 가까운 정상 패치까지의 거리를 이상 점수로 쓴다. 학습이 없다. 백본은 WideResNet-50-2와 DINOv2 ViT-S/14, ViT-B/14.
- **Dinomaly**: DINOv2 인코더를 고정하고 디코더가 특징을 복원하게 학습하는 방식. 12개 범주를 모델 하나로 다룬다.
- **지도 학습 비교군**: DINOv2 고정 특징 위에 가벼운 분할 헤드.
- **서빙**: ONNX Runtime으로 내보내 FastAPI 검사 API(이상 점수, 양품/불량 판정, 히트맵)와 단일 HTML 데모로 묶는다.

## 측정 방식
- 규칙(후보, 지표, 판정 기준)을 재기 전에 `docs/experiments.md`에 적고 커밋한다.
- 구성을 확인하고 코드를 점검하는 데는 dev 분할만 쓴다. 봉인 테스트는 단계가 끝날 때 정해 둔 것만 한 번 재고, 읽을 때마다 장부에 남긴다.
- 차이는 부트스트랩 신뢰구간이 0을 포함하지 않고 미리 정한 최소 크기를 넘을 때만 "차이 있음"으로 적는다. "판정 불가"와 "개선 없음"도 결과다.

## 하지 않는 것
- 공식 `1cls` 분할의 공개 수치 재현: 봉인 테스트 이미지와 겹친다 (`docs/experiments.md` 참고).
- MVTec AD(비상업 라이선스), EfficientAD(ImageNet 부분집합을 추가로 받아야 함), AGPL 라이브러리.
- 임베디드 장비 실측: 지연은 데스크톱 GPU(RTX 2080 Ti)와 CPU(Ryzen 5 3600)에서만 잰다.
